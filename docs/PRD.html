0. บทสรุปผู้บริหาร (TL;DR)

  • UPVerse คืออะไร: แอปเว็บ (mobile-first, ติดตั้งเป็น PWA ได้) ที่เป็น "ระบบบันทึกจริง + แดชบอร์ด + รางส่งคำสั่งที่ต้องมีคนกดยืนยัน" ของพอร์ตหุ้นสหรัฐของต้นผ่าน Webull ประเทศไทย
  • สมองวิเคราะห์ไม่ได้อยู่ในแอป — อยู่ที่ agent upverse-advisor (Claude Code) ซึ่งเขียนผล (thesis · ตั๋วเสนอ · บันทึก) เข้าแอปผ่าน /api/v1 · ตัวแอปคำนวณสิ่งที่เป็นสูตรตายตัว (สแกน · ตัวชี้วัด · กฎความเสี่ยง) โดยไม่มี LLM ฝั่งเซิร์ฟเวอร์
  • MVP (เฟส 1): พอร์ต (ดึงจริงจาก Webull เมื่อใส่กุญแจในแอป + สมุดบันทึกมือ/paper) · ราคาใกล้เรียลไทม์ · สแกน Top 10 ใน 5 โมเดล · หน้าหุ้น · watchlist · ตั๋วคำสั่ง 2 ขั้น (ส่งจริงเฉพาะ UAT) · สมุดบันทึกการตัดสินใจ · ตั้งค่า · API
  • ไม่ทำใน v1: ส่งคำสั่งเงินจริงอัตโนมัติ · ออปชัน (เฟส 2) · หลายผู้ใช้ · HK/A-shares · คำนวณภาษี
  • ประมาณการงานสร้าง: 4 สปรินต์ (~6 สัปดาห์ของ metatron) หลัง Sprint 0 พิสูจน์ Webull API ด้วยบัญชีทดสอบ

1. ปัญหาและเป้าหมาย (Problem & Goal)

1.1 ปัญหา

ต้นลงทุนหุ้นสหรัฐผ่าน Webull ไทยแบบเศษหุ้นด้วยทุนหลักพันบาท ตั้งใจเติมทุกเดือนจนเป็นพอร์ตหลักหลายล้านบาท แต่ตอนนี้ 1. ไม่มีที่เดียว ที่เห็นพอร์ตจริง + แผน + เหตุผลของทุกการตัดสินใจ (ข้อมูลอยู่ในแอปโบรกเกอร์ ความคิดอยู่ในหัว) 2. ไม่มีเครื่องสแกน ที่ตรงสไตล์ตัวเอง (พื้นฐานแนว VI ระยะกลาง + จังหวะเทคนิค + เตรียมขายออปชันในอนาคต) — screener ทั่วไปให้ลิสต์ แต่ไม่บอก "ทำไม" 3. ไม่มีวินัยเชิงระบบ กันการตัดสินใจด้วยอารมณ์ (ไล่ราคา · ถัวขาลง · ไม้ใหญ่เกิน) และไม่มี track record ไว้เรียนรู้ 4. อยากให้ AI ช่วยคิด แต่ต้องไม่ให้ AI กดซื้อเอง และไม่ให้ AI เห็นกุญแจบัญชี

ต้นทุนถ้าไม่แก้: ตัดสินใจกระจัดกระจาย · ความเสี่ยงซ้อนโดยไม่รู้ตัว · ไม่มีหลักฐานว่าวิธีไหนได้ผล → พอร์ตโตด้วยโชคมากกว่าระบบ

1.2 เป้าหมาย (วัดได้)

# เป้าหมาย วัดอย่างไร เมื่อไร
G1 เห็นพอร์ตจริง (Webull) หรือสมุดบันทึกมือ พร้อมราคาใกล้เรียลไทม์บนมือถือ ราคาเก่ากว่า 15 วินาทีในช่วงตลาดเปิดต้องมีป้าย "ค้าง" · หน้าเปิดใน < 2.5 วิ บน 4G จบเฟส 1
G2 มีรายการ Top 10 จาก 5 โมเดล อัปเดตทุกคืนหลังปิดตลาดสหรัฐ งานกลางคืนสำเร็จ ≥ 95% ของวันทำการ · ทุกรายการมี "ทำไม" จบเฟส 1
G3 ทุกคำสั่งที่ผ่านระบบมีตั๋ว + การยืนยันของต้น + audit log 100% ไม่มีทางลัด (ทดสอบด้วยการพยายามข้าม) จบเฟส 1
G4 ทุกการตัดสินใจ (รวม "ไม่ทำ") มีบันทึกในสมุด ≥ 80% ของตั๋วที่ปิดแล้วมี journal ภายใน 7 วัน 3 เดือนหลังใช้
G5 วัดผลโมเดลสแกนได้ด้วยตัวเลขจริง hit-rate / ผลตอบแทนล่วงหน้า 20-60 วัน เทียบ SPY ต่อโมเดล 90 วันหลังสแกนรอบแรก

เป้าธุรกิจ (รอง): เป็นต้นแบบ (POC) ที่ต่อยอดเป็นเครื่องมือสอนหรือขายได้ในอนาคต — ไม่ใช่เป้าของ v1 และห้ามให้เป้านี้ขยาย scope

3. หลักการออกแบบ (Principles) — ทุกข้อกำหนดด้านล่างต้องไม่ขัด 8 ข้อนี้

  1. คนกด ไม่ใช่เครื่องกด — ตั๋วทุกใบผ่าน proposed → ต้นยืนยันในหน้าจอ → ส่ง · การยืนยัน 1 ครั้งใช้กับ 1 ตั๋ว · API token ยืนยันไม่ได้
  2. UAT ก่อนเสมอ — ค่าเริ่มต้นของทุก environment คือ Webull UAT · prod เปิดได้เฉพาะจากหน้าตั้งค่าด้วยประโยคยืนยัน และมี kill switch
  3. กุญแจไม่ออกจากเซิร์ฟเวอร์ — เข้ารหัสก่อนเก็บ · แสดงแค่ 4 ตัวท้าย · ไม่ลง log · ไม่คืนผ่าน API · repo เป็น public จึงห้ามมีข้อมูลจริงในโค้ด
  4. ตัวเลขมีที่มาและเวลา — ทุกค่าที่แสดงมี source + as_of · ข้อมูลไม่ครบ = แสดง "ไม่ครบ" ไม่เติมค่า ไม่ประมาณเงียบ ๆ
  5. ค่าจาก AI ต้องมีคนยืนยัน — thesis/ตั๋ว/บันทึกที่ agent เขียนมีป้าย 🤖 และสถานะ draft จนต้นกดยืนยัน (feedback_ai_estimate_needs_human_confirm)
  6. ทุกข้อเสนอมีทางเลือกที่ 0 — ตั๋วต้องมีช่อง "ถ้าไม่ทำจะเป็นอย่างไร" และ "อะไรจะทำให้คิดผิด"
  7. ตรวจสอบย้อนหลังได้ — audit log ทุกการกระทำสำคัญ (รวมที่ถูกปฏิเสธ) · /api/v1/health บอกค่าที่บังคับใช้จริง ไม่ใช่ที่ตั้งไว้
  8. มือถือก่อน — ทุกหน้าใช้ได้ที่ 375px ด้วยนิ้วโป้งข้างเดียว · ตัวอักษรไทย ≥ 17.5px · คอนทราสต์ ≥ 4.5:1 · มืด/สว่างตามเครื่อง

upverse-advisor — agent 13. ในฐานะ agent ผมอยากอ่านพอร์ต/สแกน/ราคาผ่าน API ด้วย token ที่อ่านได้อย่างเดียว เพื่อวิเคราะห์โดยไม่แตะกุญแจโบรกเกอร์ 14. ในฐานะ agent ผมอยากเขียน thesis และตั๋วสถานะ proposed เข้าแอป เพื่อให้ต้นเห็นและยืนยันในที่เดียว 15. ในฐานะ agent ผมอยากรู้ว่าตั๋วถูกปฏิเสธเพราะกฎข้อไหน เพื่อปรับข้อเสนอ ไม่ใช่เดา

กรณีขอบ (edge cases) 16. ถ้า Webull token หมดอายุหรือ 2FA ต้องทำใหม่ ระบบต้องแสดงสถานะ "ต้องเชื่อมใหม่" และไม่ทำงานเงียบ ๆ ด้วยข้อมูลเก่า 17. ถ้าผู้ให้ราคาหลักล่ม ระบบต้องสลับไปตัวสำรองและติดป้าย "ราคาสำรอง/ดีเลย์" ทุกจุด 18. ถ้างานสแกนกลางคืนล้ม หน้าสแกนต้องบอกว่า "ข้อมูลของคืนก่อน" ไม่ใช่โชว์เหมือนใหม่ 19. ถ้าพอร์ตว่างเปล่า (ยังไม่มีอะไร) ทุกหน้าต้องมี empty state ที่บอกขั้นถัดไป

11. ความปลอดภัยและการกำกับ

  • กุญแจ: ciphertext ใน DB (AES-256-GCM · nonce ต่อรายการ) · master key ใน Vercel env เท่านั้น · หมุนกุญแจหลักได้ (re-encrypt job) · ทางเลือก: Supabase Vault (ประเมินใน Sprint 0)
  • สิทธิ์: RLS ทุกตาราง · broker_credentials ไม่มี policy ฝั่ง client · service role ใช้เฉพาะ server/jobs · ผู้ดู (viewer) อ่านเฉพาะ portfolio/scan/journal ที่ต้นเปิด
  • การยืนยันตั๋ว: เซสชันคน + ประโยคยืนยัน + idempotency + ตรวจซ้ำฝั่ง server · API token ไม่มีทางยืนยันได้
  • Kill switch สองชั้น: env TRADING_ENABLED และ settings.trading_enabled · prod ต้องผ่าน gate (§14) และมีป้ายแดงถาวร
  • Log/ข้อผิดพลาด: masking กลางสำหรับ app_key app_secret access_token authorization · ห้าม log body ของ credentials endpoint
  • Repo public: .gitignore ครอบ .env* · เปิด GitHub secret scanning + push protection · ไม่มี seed ข้อมูลจริง · ตัวอย่างในโค้ด/mockup เป็นข้อมูลสมมติและติดป้าย
  • Header ความปลอดภัย: CSP · HSTS · no-referrer สำหรับหน้าตั้งค่า · rate limit ต่อ IP/token
  • ข้อความกำกับ: ทุกหน้ามีบรรทัด "ไม่ใช่คำแนะนำจากผู้มีใบอนุญาต · ใช้ส่วนตัว" · ไม่มีฟีเจอร์แชร์พอร์ตสาธารณะใน v1

# ราคา

# หุ้น: quote + bars + indicators + EDGAR
curl -s "$B/instruments/AAPL?range=1y" | jq '{quote:.quote.price, rsi:.snapshot.rsi14, fy:.fundamentals.fy, fscore:.fundamentals.fScore}'

# รันสแกน (เจ้าของ) — เร็ว 60 ตัว หรือทั้ง S&P 500 (หลายนาที)

# ยืนยัน (เซสชันเจ้าของเท่านั้น — ต้องพิมพ์ประโยคตรงทุกตัวอักษร · idempotencyKey กันกดซ้ำ)
curl -s -X POST $B/tickets/<ID>/confirm -H "$J" -d '{"phrase":"ยืนยัน ซื้อ VOO 0.05","idempotencyKey":"abcdefgh12"}'

แบบจำลองค่าธรรมเนียม (src/lib/fees.ts · webull.co.th/pricing อ่าน 18 ก.ย. 2569)

คอมมิชชัน 0.10% ของมูลค่า ไม่มีขั้นต่ำ (ซื้อ+ขาย) · ฝั่งขาย: SEC 0.0000206 × มูลค่า (ขั้นต่ำ $0.01) + FINRA 0.000195 × จำนวนหุ้น (ขั้นต่ำ $0.01 · สูงสุด $9.79) · FX spread จาก settings.fxSpreadPct · fills ที่นำเข้าจาก Webull มี fees: 0 เพราะ API ไม่ส่งค่าธรรมเนียม — ตัวเลขในแอปเป็นค่าประมาณจากแบบจำลองนี้ · ผล: ไม้ขาย < $3 เกินกฎ 1% เสมอ

กฎความเสี่ยงที่ตรวจทุกตั๋ว (ค่าเริ่มต้น v1)

quote สด (≤ 60 วิ ตอนตลาดเปิด · fail-closed) · มูลค่า ≤ $500 · จำนวน ≤ 100 · whitelist (ราง API) · น้ำหนักหลังทำ: หุ้นเดี่ยว ≤ 10% (เตือน 8%) / แกน ETF (VOO SPY IVV VTI QQQ SCHD) ≤ 80% · เงินสดพอ + ขั้นต่ำ 5% · ความเสี่ยงต่อไม้ ≤ 1% (ยกเว้น tag DCA) · ตั๋ว/วัน ≤ 5 · ตั๋วซ้ำ · หมดอายุ · ราง API: kill switch (setting + env) · environment ตรง · เชื่อม Webull แล้ว · ขายไม่เกินที่ถือ

2FA ของ Webull — กรอกที่ไหน (จากเอกสารทางการ authentication/token)

  1. กด "เชื่อม" ในหน้าตั้งค่า → แอปเรียก POST /auth/tokens/create → token สถานะ PENDING และ Webull ส่ง SMS ไปเบอร์ที่ผูกบัญชี
  2. ในแอป Webull: Menu → Messages → OpenAPI Notifications → เปิดข้อความล่าสุด → กด "Check Now" → กรอกรหัส SMS → ยืนยัน (ภายใน 5 นาที ไม่งั้น EXPIRED)
  3. กลับมาที่หน้าตั้งค่า กด "ตรวจสถานะ" (หน้าจะตรวจให้เองทุก 5 วิ) → POST /auth/tokens/check → NORMAL = เชื่อมแล้ว
  4. token จะ INVALID ถ้าไม่มีการเรียก 15 วันติดต่อกัน → งานสแกนกลางคืนเรียก refresh ให้ · ถ้าหลุดให้กด "ขอรหัสใหม่"

แอป UPVerse ไม่มีช่องกรอกรหัส SMS โดยเจตนา — รหัสกรอกในแอป Webull เท่านั้น (เราแค่รอสถานะ)

MCP — ดึงข้อมูล/สั่งงานจาก Claude Code

upverse-mcp — ดึงข้อมูล/สั่งงาน UPVerse จาก Claude Code (หรือ MCP client อื่น)

MCP server (stdio) ที่ห่อ REST API v1 ของแอป (docs/API-UPVerse.md) เป็นเครื่องมือ 18 ตัว · ไม่มี LLM ในตัว · ทำได้เท่าที่ token มี scope — ยืนยันตั๋วไม่ได้ (เจ้าของกดในแอปเท่านั้น)

ติดตั้ง (ครั้งเดียว)

cd mcp && npm install

สร้าง API token ในแอป: ตั้งค่า → API tokens → scope ที่แนะนำ portfolio:read quotes:read scan:read theses:read theses:write tickets:propose journal:write watchlist:write แล้วเก็บไว้ที่ (ไม่อยู่ใน repo):

mkdir -p ~/.upverse && printf '%s' 'upv_…' > ~/.upverse/token && chmod 600 ~/.upverse/token

หรือตั้ง env UPVERSE_TOKEN · เปลี่ยน URL ด้วย UPVERSE_URL (ค่าเริ่มต้น https://upverse-app.vercel.app)

ใช้กับ Claude Code

.mcp.json ที่ root ของ repo ลงทะเบียน server ชื่อ upverse ไว้แล้ว — เปิด Claude Code ในโฟลเดอร์นี้ → อนุมัติ server ครั้งแรก → ถามได้เลย เช่น "ดูพอร์ต" "วิเคราะห์พอร์ต" "thesis NVDA" "สแกน M4" "เสนอตั๋วซื้อ VOO $10" ถ้าเปิดจากโฟลเดอร์อื่น: claude mcp add upverse -- node /path/to/UPVerse/mcp/upverse-mcp.mjs

หลักการวิเคราะห์ที่ใช้

หลักการวิเคราะห์หุ้นที่ UPVerse ใช้ — และที่ยังไม่ใช้ (v0.1 · 18 ก.ย. 2569)

คัดจากหลักการที่มีหลักฐาน/ประวัติยาว ไม่ใช่สูตรจากอินฟลูเอนเซอร์ · ทุกข้อระบุว่า ใช้ในแอปแล้ว (✅) · ใช้ได้เมื่อมีข้อมูล (🟡) · จงใจไม่ใช้ (⛔) พร้อมเหตุผล กติกาแกน: พื้นฐานตัดสินว่า ซื้ออะไร · เทคนิคตัดสินว่า ซื้อเมื่อไร/ออกตรงไหน · กฎความเสี่ยงตัดสินว่า เท่าไร · ไม่มีหลักการไหนแทนการเขียน thesis ก่อนซื้อได้

1 · เลือกอะไร (พื้นฐาน)

หลักการ ใจความ ในแอป ที่มา
คูเมือง + circle of competence (Buffett/Munger) อธิบายธุรกิจได้ใน 3 บรรทัด · คูเมืองแข็งขึ้นหรืออ่อนลง · ผู้บริหารเอาเงินไปทำอะไร ✅ thesis §2C ข้อ 1–3 · ตรวจโดยวง persona Berkshire letters · Munger, Poor Charlie's Almanack
Owner earnings / FCF หลังหัก SBC กำไรที่เจ้าของได้จริง = OCF − capex − ค่าตอบแทนที่จ่ายเป็นหุ้น (SBC คือต้นทุน) ✅ FCF ในสแกน · 🟡 SBC ต้องเพิ่ม tag EDGAR (บทเรียน AXON) Buffett 1986 letter · Damodaran เรื่อง SBC
Piotroski F-score 9 สัญญาณคุณภาพงบ (กำไร · กระแสเงินสด · หนี้ · margin · turnover) ✅ คำนวณจาก EDGAR (ธนาคารได้ 6/9) Piotroski (2000)
Gross profitability กำไรขั้นต้น/สินทรัพย์ ทำนายผลตอบแทนได้ดีกว่ากำไรสุทธิ 🟡 ต้องเพิ่ม GrossProfit + Assets tags Novy-Marx (2013)
Expectations investing (reverse DCF) ไม่ทายมูลค่า แต่ถามว่า "ราคานี้ต้องการโตกี่ %/ปี" แล้วตัดสินว่าเชื่อไหม ✅ "ราคานี้ต้องการโต x%/ปี" ในหน้าพอร์ต (3 ปี · 30× FCF หรือ 12× EPS · คิดลด 10%) Mauboussin & Rappaport (2001/2021)
มูลค่า 3 ฉาก + margin of safety ≥ 25% bear/base/bull ที่ย้อนสูตรได้ · ราคาน่าซื้อ = base − 25% ✅ thesis §2C ข้อ 4 (สคริปต์ journal/private/theses/) · 🟡 เครื่องคิดเลขในแอป (B5) Graham, The Intelligent Investor บท 20
Magic Formula (ROIC สูง + earnings yield สูง) จัดอันดับ "ดี+ถูก" แบบกลไก 🟡 ต้องเพิ่ม EBIT · NWC · fixed assets tags Greenblatt, The Little Book That Beats the Market (2005)
Accruals / Beneish M / Altman Z จับกำไรที่ไม่ใช่เงินสด · แต่งบัญชี · ความเสี่ยงล้มละลาย 🟡 ต้องเพิ่ม tags · ใช้เป็น "ธงแดง" ไม่ใช่คะแนน Sloan (1996) · Beneish (1999) · Altman (1968)
PEG / ประเภทหุ้นแบบ Lynch โตเร็ว · โตช้า · วัฏจักร · ฟื้นตัว · สินทรัพย์แฝง — ใช้เครื่องมือคนละชุด 🟡 บทบาทใน thesis (แกน/ดาวเทียม/รายได้) ทำหน้าที่คล้ายกัน Lynch, One Up on Wall Street (1989)

2 · ซื้อเมื่อไร / ออกตรงไหน (เทคนิค)

หลักการ ใจความ ในแอป ที่มา
Stage analysis (Weinstein) 4 ขั้น: ฐาน → ขาขึ้น → ยอด → ขาลง · ซื้อขั้น 1–2 · ห้ามถัวขั้น 4 ✅ หน้าพอร์ต: ราคา vs SMA150 + ความชัน SMA200 Weinstein (1988)
Trend template (Minervini) 8 เงื่อนไขแนวโน้มขึ้น (ราคา > SMA150/200 · SMA200 ขาขึ้น · ≥ 30% เหนือ low · ≤ 25% จาก high · RS สูง) ✅ นับ x/8 · ข้อ 8 ใช้ RS เทียบ SPY แทน RS rating Minervini (2013)
Relative strength / momentum แข็งกว่าตลาด 3–12 เดือน มีหลักฐานเชิงวิชาการ · 1 เดือนกลับทิศ · 3–5 ปีกลับทิศ ✅ RS vs SPY 1/3/6/12 เดือน · rank ในสแกน M4 Jegadeesh & Titman (1993) · Antonacci (2014)
CAN SLIM (O'Neil) กำไรโตเร่ง + ผู้นำกลุ่ม + ฐานทะลุด้วยปริมาณ + ตัดขาดทุน 7–8% 🟡 M1/M4 ใช้บางส่วน · ตัดขาดทุนใช้ 2×ATR แทน O'Neil, How to Make Money in Stocks
ฐานสะสม ≥ 4–6 สัปดาห์ + ปริมาณยืนยัน ไม่รับมีดที่กำลังตก · รอ higher low + กลับเหนือ EMA20 ด้วยปริมาณ ✅ กฎ "มีดกำลังตก" (ขั้น 4 + ร่วง > 15%/20 วัน) → ห้ามเพิ่ม Weinstein · Minervini · Wyckoff (แนวคิด)
ATR position sizing / R-multiples ขนาดไม้จากระยะถึง stop (≤ 1% ของพอร์ตต่อไม้) · เป้า ≥ 2R · time stop ✅ กฎ §3 ในตั๋ว · 🟡 ต้องรู้ก่อนว่า Webull TH ตั้ง stop กับเศษหุ้นได้ไหม Van Tharp · Turtle rules
Dual momentum สำหรับแกน ถ้า SPY 12 เดือน < T-bill → พักแกนไปพันธบัตร/เงินสด ⛔ ยังไม่ใช้ — พอร์ตเล็ก + ค่าธรรมเนียม/ภาษีจากการสลับ · ทบทวนเมื่อพอร์ต ≥ $5,000 Antonacci (2014)

3 · เท่าไร / จัดพอร์ต (ความเสี่ยง)

หลักการ ใจความ ในแอป ที่มา
Core-Satellite แกน ETF ดัชนี 70% · ดาวเทียม 20% · เงินสด 10% · เงินใหม่ไปแกนก่อน ✅ หน้าพอร์ต "สัดส่วนเงินทุน vs แผน" + "เงินเติมรอบหน้าควรไป" (เป้าจากหน้าเป้าหมาย) Bogle · Swensen (2005)
เพดานหุ้นเดี่ยว + วัดกับพอร์ตแผน ≤ 10% (เตือน 8%) · วัดกับพอร์ต 12 เดือนข้างหน้า ไม่ใช่วันนี้ ✅ เมื่อตั้งเงินเติมต่อเดือนในหน้าเป้าหมาย UPVerse §3 (วง persona 18 ก.ย.)
De minimis ไม้ลดสัดส่วน < $3 หรือค่าธรรมเนียม > 1% → ไม่บังคับขาย ใช้เงินใหม่เจือจาง ✅ UPVerse §3 (เสนอ 18 ก.ย. — ต้นเคาะ)
Rebalancing bands 5/25 ปรับสมดุลเมื่อสัดส่วนเบี่ยง 5 จุด หรือ 25% ของเป้า — ไม่ใช่ตามปฏิทิน 🟡 แสดง gap แล้ว · ตั๋ว rebalance อัตโนมัติยังไม่มี Swedroe
ห้ามถัวเฉลี่ยขาลงเมื่อ thesis พัง ถัวได้เฉพาะ thesis "เพิ่ม" ที่ยืนยัน + ราคา ≤ น่าซื้อ + ไม่ใช่มีดตก + ไม่เกินเพดาน ✅ "ถัวได้ไหม" ทุกตัวที่ขาดทุน UPVerse §2D
โยกเงินแบบมีด่าน (ไม่ไล่ performance) ต้นทางอ่อน + ปลายทางมี thesis "เพิ่ม" ยืนยัน + คะแนนต่าง ≥ 20 + ต้นทุน ≤ 1% + ถือ ≥ 30 วัน ✅ "โยกเงินไปไหน" · ผลตอบแทนย้อนหลังอย่างเดียวไม่ใช่เหตุผล Barber & Odean (2000) — ยิ่งซื้อขายบ่อย ยิ่งได้น้อย
Kelly fraction / risk parity ขนาดไม้จากความได้เปรียบ · น้ำหนักจากความผันผวน ⛔ Kelly ต้องรู้ edge ที่ยังไม่มีหลักฐาน (B9 วัดผลก่อน) · risk parity ต้องมีพันธบัตร Kelly (1956) · Bridgewater

4 · พฤติกรรม (ที่ทำให้ทุกอย่างข้างบนใช้ได้จริง)

หลักการ ในแอป ที่มา
เขียน thesis/journal ก่อนซื้อ — "ไม่มี thesis เขียนไว้ = ไม่มีตำแหน่ง" ✅ ป้าย "ไม่มี thesis — ห้ามเพิ่ม/ถัว" · 🟡 ด่านตั๋ว (A1) Kahneman · Klein pre-mortem · Pabrai/Spier checklist
"อะไรจะทำให้ผมคิดผิด" เป็นเรื่องธุรกิจ ไม่ใช่ราคา ✅ thesis ทุกฉบับ · 🟡 ตรวจอัตโนมัติกับงบใหม่ (B2) Buffett: ราคาไม่ได้บอกว่าคุณผิด
ทางเลือกที่ 0 เสมอ ✅ thesis + ตั๋ว Munger: inversion
วง persona + lucifer ก่อนไม้ใหญ่ ✅ 5 persona × 2 รอบ ทุก thesis UPVerse §6
วัดผลตัวเอง (hit rate · R เฉลี่ย · thesis แม่นไหม) 🟡 B9 — ต้องมีประวัติ ≥ 1 ไตรมาส Tetlock, Superforecasting

คะแนน 0–100 ที่หน้าพอร์ตใช้ (agent §2B · ต้นปรับน้ำหนักได้)

คุณภาพ 25 (F-score · ROE · FCF margin · รายได้โต 3 ปี) · มูลค่า 25 (P/FCF หรือ P/E · ราคา ≤ น่าซื้อของ thesis) · จังหวะ 30 (trend template x/8 · RS vs SPY 6 เดือน) · ปัจจัยกระตุ้น 10 (thesis "เพิ่ม" · ติดสแกน) · หักความเสี่ยง ≤ 10 (ผันผวน > 5%/วัน · ต่ำกว่า high > 40% · ไม่มี thesis · ขาลง) — ทุกคะแนนมี "ทำไม" กดดูได้

  • ผลตอบแทนพอร์ตเทียบ SPY ต้องมีประวัติ ≥ 60 วัน และยังเป็นแบบง่าย (ไม่หักเงินเติม — TWR มาทีหลัง)
  • ป้าย "ควรทำอะไร" ทุกป้ายเป็นข้อเสนอจากกฎ · ต้นตัดสินใจเองผ่านตั๋ว · ไม่ใช่คำแนะนำจากผู้มีใบอนุญาต

## 0. บทสรุปผู้บริหาร (TL;DR)

- **UPVerse คืออะไร:** แอปเว็บ (mobile-first, ติดตั้งเป็น PWA ได้) ที่เป็น **"ระบบบันทึกจริง + แดชบอร์ด + รางส่งคำสั่งที่ต้องมีคนกดยืนยัน"** ของพอร์ตหุ้นสหรัฐของต้นผ่าน Webull ประเทศไทย
- **สมองวิเคราะห์ไม่ได้อยู่ในแอป** — อยู่ที่ agent `upverse-advisor` (Claude Code) ซึ่งเขียนผล (thesis · ตั๋วเสนอ · บันทึก) เข้าแอปผ่าน `/api/v1` · ตัวแอปคำนวณสิ่งที่เป็นสูตรตายตัว (สแกน · ตัวชี้วัด · กฎความเสี่ยง) โดยไม่มี LLM ฝั่งเซิร์ฟเวอร์
- **MVP (เฟส 1):** พอร์ต (ดึงจริงจาก Webull เมื่อใส่กุญแจในแอป + สมุดบันทึกมือ/paper) · ราคาใกล้เรียลไทม์ · สแกน Top 10 ใน **5 โมเดล** · หน้าหุ้น · watchlist · ตั๋วคำสั่ง 2 ขั้น (ส่งจริงเฉพาะ UAT) · สมุดบันทึกการตัดสินใจ · ตั้งค่า · API
- **ไม่ทำใน v1:** ส่งคำสั่งเงินจริงอัตโนมัติ · ออปชัน (เฟส 2) · หลายผู้ใช้ · HK/A-shares · คำนวณภาษี
- **ประมาณการงานสร้าง:** 4 สปรินต์ (~6 สัปดาห์ของ metatron) หลัง Sprint 0 พิสูจน์ Webull API ด้วยบัญชีทดสอบ

## 1. ปัญหาและเป้าหมาย (Problem & Goal)

### 1.1 ปัญหา
ต้นลงทุนหุ้นสหรัฐผ่าน Webull ไทยแบบเศษหุ้นด้วยทุนหลักพันบาท ตั้งใจเติมทุกเดือนจนเป็นพอร์ตหลักหลายล้านบาท แต่ตอนนี้
1. **ไม่มีที่เดียว** ที่เห็นพอร์ตจริง + แผน + เหตุผลของทุกการตัดสินใจ (ข้อมูลอยู่ในแอปโบรกเกอร์ ความคิดอยู่ในหัว)
2. **ไม่มีเครื่องสแกน** ที่ตรงสไตล์ตัวเอง (พื้นฐานแนว VI ระยะกลาง + จังหวะเทคนิค + เตรียมขายออปชันในอนาคต) — screener ทั่วไปให้ลิสต์ แต่ไม่บอก "ทำไม"
3. **ไม่มีวินัยเชิงระบบ** กันการตัดสินใจด้วยอารมณ์ (ไล่ราคา · ถัวขาลง · ไม้ใหญ่เกิน) และไม่มี track record ไว้เรียนรู้
4. อยากให้ AI ช่วยคิด **แต่ต้องไม่ให้ AI กดซื้อเอง** และไม่ให้ AI เห็นกุญแจบัญชี

**ต้นทุนถ้าไม่แก้:** ตัดสินใจกระจัดกระจาย · ความเสี่ยงซ้อนโดยไม่รู้ตัว · ไม่มีหลักฐานว่าวิธีไหนได้ผล → พอร์ตโตด้วยโชคมากกว่าระบบ

### 1.2 เป้าหมาย (วัดได้)

|---|---|---|---|

| G2 | มีรายการ Top 10 จาก 5 โมเดล อัปเดตทุกคืนหลังปิดตลาดสหรัฐ | งานกลางคืนสำเร็จ ≥ 95% ของวันทำการ · ทุกรายการมี "ทำไม" | จบเฟส 1 |

## 3. หลักการออกแบบ (Principles) — ทุกข้อกำหนดด้านล่างต้องไม่ขัด 8 ข้อนี้

1. **คนกด ไม่ใช่เครื่องกด** — ตั๋วทุกใบผ่าน proposed → ต้นยืนยันในหน้าจอ → ส่ง · การยืนยัน 1 ครั้งใช้กับ 1 ตั๋ว · API token ยืนยันไม่ได้
2. **UAT ก่อนเสมอ** — ค่าเริ่มต้นของทุก environment คือ Webull UAT · prod เปิดได้เฉพาะจากหน้าตั้งค่าด้วยประโยคยืนยัน และมี kill switch
3. **กุญแจไม่ออกจากเซิร์ฟเวอร์** — เข้ารหัสก่อนเก็บ · แสดงแค่ 4 ตัวท้าย · ไม่ลง log · ไม่คืนผ่าน API · repo เป็น public จึงห้ามมีข้อมูลจริงในโค้ด
4. **ตัวเลขมีที่มาและเวลา** — ทุกค่าที่แสดงมี `source` + `as_of` · ข้อมูลไม่ครบ = แสดง "ไม่ครบ" ไม่เติมค่า ไม่ประมาณเงียบ ๆ
5. **ค่าจาก AI ต้องมีคนยืนยัน** — thesis/ตั๋ว/บันทึกที่ agent เขียนมีป้าย 🤖 และสถานะ draft จนต้นกดยืนยัน (`feedback_ai_estimate_needs_human_confirm`)
6. **ทุกข้อเสนอมีทางเลือกที่ 0** — ตั๋วต้องมีช่อง "ถ้าไม่ทำจะเป็นอย่างไร" และ "อะไรจะทำให้คิดผิด"
7. **ตรวจสอบย้อนหลังได้** — audit log ทุกการกระทำสำคัญ (รวมที่ถูกปฏิเสธ) · `/api/v1/health` บอกค่าที่บังคับใช้จริง ไม่ใช่ที่ตั้งไว้
8. **มือถือก่อน** — ทุกหน้าใช้ได้ที่ 375px ด้วยนิ้วโป้งข้างเดียว · ตัวอักษรไทย ≥ 17.5px · คอนทราสต์ ≥ 4.5:1 · มืด/สว่างตามเครื่อง

## 5. เรื่องราวผู้ใช้ (User Stories) — เรียงตามความสำคัญ

**ต้น — เจ้าของพอร์ต**
1. ในฐานะเจ้าของพอร์ต ผมอยากใส่ App Key/Secret ของ Webull ในหน้าตั้งค่าแล้วกด "ทดสอบเชื่อม" เพื่อให้แอปดึงพอร์ตจริงได้โดยไม่ต้องแตะโค้ดหรือไฟล์ env
2. ในฐานะเจ้าของพอร์ต ผมอยากบันทึกซื้อ/ขาย/ปันผล/ฝากเงินด้วยมือ (เศษหุ้นได้) ระหว่างที่ยังไม่มี API เพื่อให้พอร์ตในแอปตรงกับของจริง
3. ในฐานะเจ้าของพอร์ต ผมอยากเห็นมูลค่าพอร์ตเป็น USD และ THB พร้อมราคาที่อัปเดตเองระหว่างตลาดเปิด เพื่อรู้สถานะโดยไม่ต้องเปิดแอปโบรกเกอร์
4. ในฐานะเจ้าของพอร์ต ผมอยากเห็น Top 10 ของแต่ละโมเดลพร้อม "ทำไม" 1 ย่อหน้า เพื่อเลือกตัวที่จะไปศึกษาต่อ ไม่ใช่ได้แค่ลิสต์
5. ในฐานะเจ้าของพอร์ต ผมอยากเห็นตั๋วคำสั่งที่ครบทุกช่อง (ราคา · จำนวน · ตัดขาดทุน · % พอร์ตหลังทำ · เหตุผล · ทางเลือกที่ 0) และผ่านกฎความเสี่ยงหรือไม่ ก่อนพิมพ์ยืนยัน เพื่อไม่ตัดสินใจด้วยอารมณ์
6. ในฐานะเจ้าของพอร์ต ผมอยากให้ระบบไม่ยอมส่งตั๋วที่ผิดกฎ (เกินเพดาน · หุ้นนอก whitelist · ราคาค้าง) เพื่อกันตัวเองในวันที่ใจร้อน
7. ในฐานะเจ้าของพอร์ต ผมอยากบันทึกว่าตอนตัดสินใจรู้สึกอย่างไรและคาดหวังอะไร แล้วให้ระบบเตือนย้อนมาดูผลใน 30/90 วัน เพื่อเรียนรู้จากตัวเอง
8. ในฐานะเจ้าของพอร์ต ผมอยากใส่เป้า (บาท · ปี · เติมต่อเดือน) แล้วเห็นว่าต้องได้ผลตอบแทนเท่าไรและตอนนี้อยู่ตรงไหน เพื่อรู้ว่าคันโยกจริงคือเติมเพิ่มหรือยืดเวลา
9. ในฐานะเจ้าของพอร์ต ผมอยากตั้ง watchlist พร้อมโซนราคาที่จะเข้า และรับแจ้งเตือนทาง LINE เมื่อราคาถึง เพื่อไม่ต้องเฝ้าจอ
10. ในฐานะเจ้าของพอร์ต ผมอยากเห็นว่าโมเดลสแกนไหน "แม่น" จริงจากผลย้อนหลัง เพื่อปรับน้ำหนักด้วยหลักฐาน
11. ในฐานะเจ้าของพอร์ต ผมอยากสลับ UAT/เงินจริงได้จากหน้าตั้งค่าเท่านั้น และเห็นชัดตลอดเวลาว่าอยู่โหมดไหน เพื่อไม่ส่งเงินจริงโดยไม่ตั้งใจ
12. ในฐานะเจ้าของพอร์ต ผมอยากให้แอปใช้ได้ดีบนมือถือขณะนั่งดูตอนกลางคืน (โหมดมืด · ตัวหนังสือใหญ่พอ) เพื่อไม่ต้องเปิดคอม

**`upverse-advisor` — agent**
13. ในฐานะ agent ผมอยากอ่านพอร์ต/สแกน/ราคาผ่าน API ด้วย token ที่อ่านได้อย่างเดียว เพื่อวิเคราะห์โดยไม่แตะกุญแจโบรกเกอร์
14. ในฐานะ agent ผมอยากเขียน thesis และตั๋วสถานะ proposed เข้าแอป เพื่อให้ต้นเห็นและยืนยันในที่เดียว
15. ในฐานะ agent ผมอยากรู้ว่าตั๋วถูกปฏิเสธเพราะกฎข้อไหน เพื่อปรับข้อเสนอ ไม่ใช่เดา

**กรณีขอบ (edge cases)**
16. ถ้า Webull token หมดอายุหรือ 2FA ต้องทำใหม่ ระบบต้องแสดงสถานะ "ต้องเชื่อมใหม่" และไม่ทำงานเงียบ ๆ ด้วยข้อมูลเก่า
17. ถ้าผู้ให้ราคาหลักล่ม ระบบต้องสลับไปตัวสำรองและติดป้าย "ราคาสำรอง/ดีเลย์" ทุกจุด
18. ถ้างานสแกนกลางคืนล้ม หน้าสแกนต้องบอกว่า "ข้อมูลของคืนก่อน" ไม่ใช่โชว์เหมือนใหม่
19. ถ้าพอร์ตว่างเปล่า (ยังไม่มีอะไร) ทุกหน้าต้องมี empty state ที่บอกขั้นถัดไป

### F2 พอร์ต (P0)

**F2.1 แหล่งพอร์ต (accounts)** — บัญชี 2 ชนิด: `webull_live` (sync จาก API) และ `manual_paper` (สมุดบันทึกมือ) · มีได้หลายบัญชี · หน้าพอร์ตมีสวิตช์ "รวมทุกบัญชี / ทีละบัญชี" และป้ายชนิดบัญชีเสมอ

**F2.3 สมุดบันทึกมือ / paper** — เพิ่มรายการ: ซื้อ · ขาย · ปันผล · ค่าธรรมเนียม · ฝาก · ถอน · แลกเงิน (บันทึก USD/THB rate) · แตกหุ้น · จำนวนเป็นทศนิยม 6 ตำแหน่ง (เศษหุ้น) · คำนวณต้นทุนเฉลี่ยและล็อต (FIFO) · แก้/ลบได้พร้อม audit · นำเข้าไฟล์ CSV จาก Webull **[ยังไม่ยืนยันรูปแบบไฟล์ — ต้นส่งตัวอย่าง]** · ตั๋วที่ fill ในโหมดรางส่งมือ (F6.6) กดสร้างรายการได้ทันที

**F2.4 ราคาใกล้เรียลไทม์** — หน้าพอร์ต/หุ้น/ตั๋ว poll `GET /api/v1/quotes?symbols=` ทุก 10 วินาที (ตลาดเปิด) · 60 วินาที (ก่อน/หลังตลาด) · หยุดเมื่อปิด · เซิร์ฟเวอร์แคช 5 วินาทีต่อสัญลักษณ์ · แสดงสถานะตลาด (ก่อนเปิด/เปิด/หลังปิด/ปิด) และเวลา ET+ICT · quote เก่ากว่า 15 วินาทีในช่วงเปิด → ป้าย "ค้าง"
**F2.5 วิเคราะห์** (คำนวณในแอป ไม่ใช่ AI)

### F6 ตั๋วคำสั่ง (P0) — หัวใจของความปลอดภัย
**F6.1 โครงตั๋ว (stock)** — บัญชี · ซื้อ/ขาย · สัญลักษณ์ · จำนวน (ทศนิยม 6) หรือมูลค่า USD · ชนิดคำสั่ง (`LIMIT` ค่าเริ่มต้น · `MARKET` ต้องติ๊กยอมรับ) · ราคา limit · ตัดขาดทุน · เป้า · R:R · % พอร์ตหลังทำ · thesis ที่อ้าง · เหตุผล 3 บรรทัด · **ทางเลือกที่ 0** · **อะไรจะทำให้คิดผิด** · หมดอายุ (ค่าเริ่มต้น 3 วันทำการ) · เวอร์ชันกฎที่ใช้ตรวจ · environment
**F6.2 สถานะ** — `proposed` → `confirmed` → `sent` → `filled` / `partially_filled` / `cancelled` / `rejected` / `expired` · ทุกการเปลี่ยนสถานะลง `order_log` (ใคร · เมื่อไร · จาก/ไป · เหตุผล)
**F6.3 ตรวจกฎ (รันตอนสร้างและตอนยืนยัน)** — รายการตรวจจาก F1.3 + ตรวจ quote ไม่ค้าง + ตั๋วซ้ำ (สัญลักษณ์/ทางเดียวกันที่ยังเปิด) + ไม่หมดอายุ + environment ตรงกับที่บัญชีอนุญาต · ผลเป็นรายการ ✅/⚠️/⛔ พร้อมตัวเลขจริง · ⛔ ตัวเดียว = ยืนยันไม่ได้
**F6.4 ยืนยัน** — ต้น (เซสชันคน) เปิดตั๋ว → เห็น **preview จาก Webull** (มูลค่า · ค่าธรรมเนียมโดยประมาณ) ถ้า API รองรับ **[ยังไม่ยืนยันว่า TH มี preview endpoint]** → พิมพ์ประโยคยืนยันที่ระบบสร้าง เช่น `ยืนยัน ซื้อ AAPL 0.5` → `confirmed` → ส่งทันที (`sent`) · ปุ่มยืนยันปิดใช้จนกว่าประโยคจะตรงและการตรวจกฎเป็นเขียว/เหลืองทั้งหมด
**F6.5 ส่งคำสั่ง (API rail)** — เรียก Webull `place_order` ด้วย environment ปัจจุบัน · เก็บ `broker_order_id` · ติดตามสถานะด้วย poll ทุก 30 วินาทีจนจบ (gRPC event = เฟส 3) · fill → สร้าง `transactions` และเปิดหน้าต่าง journal ทันที
**F6.6 รางส่งมือ (Manual rail — ค่าเริ่มต้นของเฟส 1 จนกว่า API ผ่านการทดสอบ)** — ปุ่ม "ทำในแอป Webull" แสดงรายละเอียดคำสั่งแบบก๊อปได้ + deep link เปิดแอป **[ยังไม่ยืนยันว่า Webull TH มี URL scheme]** → ต้นทำเอง → กลับมากด "ทำแล้ว ราคา __ จำนวน __" → สร้าง transaction (source `manual_after_ticket`) และตั๋วเป็น `filled` · ใช้ได้กับบัญชี `manual_paper` ด้วย (ทดลองระบบก่อนมีกุญแจ)
**F6.7 ขนาดไม้** — เครื่องคิด: ทุน · %เสี่ยง · ราคาเข้า · ตัดขาดทุน (พรีฟิล 2×ATR14 หรือ swing low) → จำนวนหุ้น (เศษได้) · ปรับตามเพดาน F1.3 · แสดง "R ต่อไม้ = $x"
**F6.8 ตั๋วชุด DCA** — จากแผน F8 สร้างตั๋วหลายใบในครั้งเดียว (แกน/ดาวเทียมตามสัดส่วน) แต่ยืนยันทีละใบ
- [ ] พยายามเรียก `POST /api/v1/tickets/{id}/confirm` ด้วย API token → 403 เสมอ
- [ ] ตั๋วที่มูลค่าเกินเพดาน → ⛔ และปุ่มยืนยันปิดใช้ · เปลี่ยนเพดาน (เวอร์ชันใหม่) → ตั๋วเดิมยังอ้างเวอร์ชันเก่าและต้องตรวจใหม่ก่อนยืนยัน
- [ ] ยืนยันตั๋วเดียวกันซ้ำ (double tap) → ส่งครั้งเดียว (idempotency key)
- [ ] environment=prod ขณะ `TRADING_ENABLED=false` → ส่งไม่ได้ทุกกรณี และ health รายงาน `trading_enabled=false`
- **[ยังไม่ยืนยัน]** Webull TH รับคำสั่งเศษหุ้น/มูลค่าผ่าน API หรือไม่ (ตัวอย่างในเอกสารมีแค่ `entrust_type: QTY`) — ถ้าไม่ได้ ตั๋วเศษหุ้นจะบังคับใช้รางส่งมือ

### M1 — กลับตัว + วอลุ่มผิดปกติ ("หุ้นเด่นที่กำลังกลับตัว")
- **ตอบคำถาม:** ตัวไหนเพิ่งเปลี่ยนจังหวะจากลง/พักตัว เป็นขึ้น พร้อมเงินไหลเข้าผิดปกติ
- **บริบทก่อนหน้า (ต้องมีอย่างน้อย 1):** ราคาปิดต่ำกว่า EMA20 ≥ 10 ใน 15 วันก่อนหน้า · หรือ ราคาลงจากจุดสูง 52 สัปดาห์ ≥ 15%
- **สัญญาณวันล่าสุด (ต้องครบ):** ปิดเหนือ high ของวันก่อน · ปิดเหนือ EMA20 · ปริมาณ ≥ 2.0 × ค่าเฉลี่ย 50 วัน · ปิดในครึ่งบนของช่วงวัน (≥ 60%)
- **คะแนน:** ปริมาณเทียบเฉลี่ย 0–30 (2× = 15 · 3× = 25 · ≥ 4× = 30) · คุณภาพการยืนกลับ 0–20 (เหนือ EMA20 +10 · SMA50 +5 · SMA200 +5) · ความแข็งแท่ง 0–15 · RS 20 วันเทียบ SPY 0–15 · ประตูพื้นฐาน 0–20 (F-score ≥ 5 +10 · FCF บวก +10) · **หัก:** งบภายใน 5 วัน −10 · ขึ้นวันเดียว > 15% −10 (เสี่ยง blow-off)
- **คอลัมน์:** ราคา · %วัน · ปริมาณ/เฉลี่ย · ระยะจาก EMA20/SMA50/SMA200 · RSI14 · วันงบ · คะแนน
- **ทำไม (แม่แบบ):** "ปิดเหนือ EMA20 ครั้งแรกใน {n} วัน ด้วยปริมาณ {x}× ค่าเฉลี่ย · ปิดที่ {p}% ของช่วงวัน · แข็งกว่า SPY {rs}% ใน 20 วัน · {ป้ายพื้นฐาน}"
- **กับดัก:** กลับตัวหลอกบ่อย → agent ต้องรอ follow-through 1–3 วันก่อนเสนอตั๋ว · ตัดขาดทุนใต้ low ของวันสัญญาณ · ห้ามไล่หลังขึ้นไปแล้ว > 5%
- **วัดผล:** ผลตอบแทน 5/20 วัน vs SPY · % ที่ไม่หลุด low วันสัญญาณใน 10 วัน

### M2 — ดาวรุ่ง VI ("VI เด่น อนาคตดี")
- **ตอบคำถาม:** ธุรกิจคุณภาพที่โตจริง ราคาไม่แพงเกินเหตุ (Quality Growth at a Reasonable Price)
- **ตะแกรง:** รายได้โตเฉลี่ย 3 ปี ≥ 10% · กำไรต่อหุ้นหรือ FCF/หุ้น โต 3 ปี ≥ 10% · ROIC ≥ 15% (หรือ ROE ≥ 15% เมื่อ หนี้/ทุน ≤ 1) · อัตรากำไรขั้นต้นไม่ถดถอย (≥ ค่าเฉลี่ย 3 ปี − 2 จุด) · FCF margin ≥ 10% · หนี้สุทธิ/EBITDA ≤ 2 หรือเงินสดสุทธิ · จำนวนหุ้นไม่เพิ่ม > 2%/ปี · มูลค่า: PEG ≤ 1.5 **หรือ** EV/EBITDA ≤ ค่ามัธยฐาน 5 ปีของตัวเอง
- **คะแนน:** การเติบโต 25 · คุณภาพ (ROIC · margin) 25 · งบดุล 15 · มูลค่า 25 · บริบทเทคนิค 10 (เหนือ SMA200 +10)
- **ทำไม:** "รายได้โต {g}%/ปี (3 ปี) · ROIC {r}% · FCF margin {f}% · EV/EBITDA {v} เทียบมัธยฐาน 5 ปี {m} · {สถานะแนวโน้ม}"
- **กับดัก:** หุ้นโตมักถูกตั้งราคาไว้สมบูรณ์แบบ · ตรวจรายการพิเศษครั้งเดียว (one-off) · ข้อมูลประมาณการชั้น 2 คลาดเคลื่อนได้ → ต้องมี thesis ก่อนตั๋วเสมอ
- **วัดผล:** 60 วัน และ 6/12 เดือน vs SPY

### M3 — ของถูกมีเหตุผล (Deep Value / Turnaround)
- **ตอบคำถาม:** ตัวไหนถูกเพราะตลาดทิ้ง แต่ตัวเลขกำลังดีขึ้น (ไม่ใช่ถูกเพราะกำลังพัง)
- **ตะแกรง:** P/FCF ≤ 12 หรือ EV/EBIT ≤ 10 หรือ (P/B ≤ 1.5 และ ROE ≥ 8%) · Piotroski F-score ≥ 7 · ราคาต่ำกว่าจุดสูง 52 สัปดาห์ ≥ 20% · **สัญญาณนิ่ง:** ปิดเหนือ SMA50 หรือ RS 3 เดือนดีขึ้นต่อเนื่อง · ปันผลปลอดภัย (payout ≤ 70%) ให้คะแนนเพิ่ม · **ตัดทิ้ง:** หนี้สุทธิ/EBITDA > 3 · FCF ติดลบ 2 ใน 3 ปี · Altman Z < 1.8
- **คะแนน:** ความถูก 35 · คุณภาพดีขึ้น (F-score) 25 · งบดุล 15 · การนิ่ง/เทคนิค 15 · ปัจจัยหนุน (ซื้อหุ้นคืน · ผู้บริหารซื้อ — เมื่อมีข้อมูล) 10
- **ทำไม:** "P/FCF {x} · F-score {f}/9 · ต่ำกว่าจุดสูง 52 สัปดาห์ {d}% แต่ยืนเหนือ SMA50 มา {n} วัน · หนี้สุทธิ/EBITDA {l}"
- **กับดัก:** value trap · ห้ามถัวเฉลี่ยขาลงถ้า thesis พัง · ต้องรู้ว่า "ทำไมถูก"
- **วัดผล:** 6/12 เดือน vs SPY

### M4 — ผู้นำแนวโน้ม (Trend Leader — แม่แบบแนวโน้มแบบ Minervini + RS)
- **ตอบคำถาม:** ตัวไหนอยู่ในแนวโน้มขึ้นที่แข็งแรงและแข็งกว่าตลาด และตอนนี้อยู่ใกล้จุดเข้าที่มีเหตุผล
- **ตะแกรง:** ปิด > SMA50 > SMA150 > SMA200 · SMA200 สูงกว่าเมื่อ 22 วันก่อน (ยกตัวขึ้น ≥ 1 เดือน) · ปิด ≥ 1.3 × ต่ำสุด 52 สัปดาห์ · ปิด ≥ 0.75 × สูงสุด 52 สัปดาห์ · RS rank ≥ 70 (เปอร์เซ็นไทล์ในจักรวาลของผลตอบแทนถ่วงน้ำหนัก 3/6/12 เดือน)
- **สถานะจุดเข้า:** ระยะจาก EMA21 ≤ 5% และปริมาณ 5 วันล่าสุด < ค่าเฉลี่ย 50 วัน = "ใกล้จุดเข้า" · 5–10% = "รอ" · > 10% = "ไล่ราคาแล้ว"
- **คะแนน:** RS 35 · โครงสร้างแนวโน้ม 25 · ใกล้จุดเข้า 20 · พื้นฐาน (กำไร 2 ไตรมาสล่าสุดโต ≥ 15%) 20
- **ทำไม:** "RS rank {r} · เหนือ SMA200 ที่ยกตัว {m} เดือน · ห่าง EMA21 {d}% ({สถานะ}) · กำไรไตรมาสล่าสุด {e}%"
- **กับดัก:** momentum พลิกเร็ว → ตัดขาดทุน 7–8% หรือใต้ swing low · ห้ามซื้อตอน "ไล่ราคาแล้ว"
- **วัดผล:** 20/60 วัน vs SPY · % หลุดตัดขาดทุนใน 20 วัน

### M5 — เครื่องจ่ายเงิน (Dividend Compounder + ผู้สมัครขายพรีเมียม)
- **ตอบคำถาม:** ตัวไหนจ่ายเงินสม่ำเสมอ โตได้ ปลอดภัย และเหมาะจะทำ CSP/covered call ในเฟส 2–3
- **ตะแกรง:** ปันผลเพิ่มติดต่อกัน ≥ 5 ปี (หรือ CAGR ปันผล 5 ปี ≥ 5%) · payout ≤ 60% (FCF payout ≤ 70%) · FCF yield ≥ 4% หรือ อัตราปันผล ≥ 2.5% · หนี้สุทธิ/EBITDA ≤ 2.5 · beta ≤ 1.2 · **ราคาต่อหุ้น ≤ 150 USD** (ล็อต 100 หุ้น ≤ 15,000 USD — พารามิเตอร์ `max_lot_price`) · IV rank ≥ 30 ให้คะแนนเพิ่ม (เมื่อมีข้อมูลออปชัน; ไม่มี = ข้าม ไม่หัก)
- **คะแนน:** ความปลอดภัยของปันผล 30 · การเติบโต 20 · มูลค่า (อัตราปันผลเทียบเฉลี่ย 5 ปี) 20 · ความน่าสนใจของพรีเมียม 15 · ล็อตจ่ายไหว 15
- **คอลัมน์พิเศษ:** "เงินสดที่ต้องกันสำหรับ CSP ที่ strike ≈ ราคา = {ราคา × 100}"
- **ทำไม:** "ปันผลโต {n} ปีติด · payout {p}% · FCF yield {f}% · ล็อต 100 หุ้น ≈ ${lot} · {IV rank ถ้ามี}"
- **กับดัก:** yield trap (ปันผลสูงเพราะราคาพัง) → ต้องผ่านตะแกรงหนี้และ FCF
- **วัดผล:** ผลตอบแทนรวม 12 เดือน (รวมปันผล) vs SPY

### M6 (P1) — งบเซอร์ไพรส์ (Post-Earnings Drift)
- รายงานงบภายใน 5 วันทำการ · EPS surprise ≥ +5% และรายได้ surprise ≥ +2% · เปิดกระโดด ≥ 3% ด้วยปริมาณ ≥ 2× · ยังรักษา ≥ 50% ของช่องว่างหลัง 3 วัน · ต้องใช้ข้อมูลประมาณการ (ชั้น 2) จึงเป็น P1 · วัดผล 20/60 วัน

## 11. ความปลอดภัยและการกำกับ

- **กุญแจ:** ciphertext ใน DB (AES-256-GCM · nonce ต่อรายการ) · master key ใน Vercel env เท่านั้น · หมุนกุญแจหลักได้ (re-encrypt job) · ทางเลือก: Supabase Vault (ประเมินใน Sprint 0)
- **สิทธิ์:** RLS ทุกตาราง · `broker_credentials` ไม่มี policy ฝั่ง client · service role ใช้เฉพาะ server/jobs · ผู้ดู (`viewer`) อ่านเฉพาะ portfolio/scan/journal ที่ต้นเปิด
- **การยืนยันตั๋ว:** เซสชันคน + ประโยคยืนยัน + idempotency + ตรวจซ้ำฝั่ง server · API token ไม่มีทางยืนยันได้
- **Kill switch สองชั้น:** env `TRADING_ENABLED` และ `settings.trading_enabled` · prod ต้องผ่าน gate (§14) และมีป้ายแดงถาวร
- **Log/ข้อผิดพลาด:** masking กลางสำหรับ `app_key` `app_secret` `access_token` `authorization` · ห้าม log body ของ credentials endpoint
- **Repo public:** `.gitignore` ครอบ `.env*` · เปิด GitHub secret scanning + push protection · ไม่มี seed ข้อมูลจริง · ตัวอย่างในโค้ด/mockup เป็นข้อมูลสมมติและติดป้าย
- **Header ความปลอดภัย:** CSP · HSTS · no-referrer สำหรับหน้าตั้งค่า · rate limit ต่อ IP/token
- **ข้อความกำกับ:** ทุกหน้ามีบรรทัด "ไม่ใช่คำแนะนำจากผู้มีใบอนุญาต · ใช้ส่วนตัว" · ไม่มีฟีเจอร์แชร์พอร์ตสาธารณะใน v1
- **ข้อมูลส่วนบุคคล:** เก็บเฉพาะอีเมลผู้ใช้ · ไม่เก็บเลขบัตร/บัญชีธนาคาร · หมายเลขบัญชีโบรกเกอร์เก็บแบบ mask
